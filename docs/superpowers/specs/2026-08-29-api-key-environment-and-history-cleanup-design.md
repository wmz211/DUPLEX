# API Key 环境变量迁移与 Git 历史清理设计

## 目标

移除仓库当前版本及全部 Git 历史中的 DeepSeek、Bocha 和 Qwen API Key，改为只从环境变量读取，同时保留用户现有源码、测试和文档修改。清理后的远端 `master` 不得包含已知密钥。

## 范围

- 使用 `DEEPSEEK_API_KEY`、`BOCHA_API_KEY`、`QWEN_API_KEY` 三个环境变量。
- 删除 `efi_pilot/main.py`、`qwen_search.py` 和 `predict_factuality.py` 中的硬编码 Key。
- CLI 不再接受 API Key 参数，避免密钥进入命令历史或进程参数。
- 缺少必要环境变量时，在发起 API 请求前以不包含敏感值的错误信息终止。
- 新增 `.env.example`，只包含变量名和空值；项目不自动加载 `.env`，不新增依赖。
- 新增或完善 `.gitignore`，排除 `.env`、Python 缓存、IDE 配置、日志、生成结果和本地大数据文件。
- 精选提交当前工作区中的源码、测试和文档；不提交缓存、IDE 配置、日志、结果、数据集及论文附件。
- 重写所有可达 Git 历史中的已知密钥并强制更新 `origin/master`。

## 配置与数据流

入口脚本通过 `os.environ` 读取三个变量，并把值传入现有配置字典。`efi_pilot` 内部的客户端创建和调用接口保持不变，避免扩大重构范围。独立脚本采用同样的变量名和缺失检查。

`.env.example` 仅用于说明配置格式。Windows PowerShell 用户可在运行前设置：

```powershell
$env:DEEPSEEK_API_KEY = "..."
$env:BOCHA_API_KEY = "..."
$env:QWEN_API_KEY = "..."
```

## 错误处理

- 启动时汇总缺失的环境变量名，一次性报告；错误中不显示任何 Key 内容。
- 对仅使用部分服务的运行模式，只要求该模式实际需要的变量。
- 搜索或模型 API 的既有网络异常处理保持不变。

## Git 提交与历史清理

1. 先完成环境变量迁移、忽略规则和测试。
2. 仅暂存源码、测试、文档和配置示例，保留其余本地文件不动。
3. 创建正常功能提交。
4. 使用 `git-filter-repo` 的精确文本替换功能清除全部已知 Key；替换规则只匹配已确认的完整密钥，不做宽泛字符串删除。
5. 扫描当前工作树、索引及所有可达提交，确认不存在 `sk-...`、`tvly-...` 等真实密钥。
6. 强制推送改写后的 `master` 至 `origin`。因为提交哈希会变化，其他克隆需要重新克隆或将本地分支重置到新历史。

## 验证

- 为环境变量读取、缺失配置错误和已有客户端行为运行或补充单元测试。
- 运行项目现有测试套件和 Python 编译检查。
- 使用脱敏扫描检查工作树与全部提交。
- 确认 `git status` 中未意外暂存数据集、日志、结果、缓存或 IDE 文件。
- 推送后获取远端引用，确认远端 `master` 指向改写后的提交。

## 安全边界

Git 历史清理不能撤销已泄露凭据。用户必须在 DeepSeek、Bocha 和 Qwen 控制台撤销旧 Key 并创建新 Key；新 Key 只能通过本地环境变量提供，不能写回仓库。
